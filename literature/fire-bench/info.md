## Что измеряет

Способность агента пройти **полный цикл эмпирического исследования**: спланировать, написать код, запустить, сделать вывод. Ответ — опубликованный вывод (insight) недавней статьи о поведении LLM (§1). Авторы называют постановку **constrained rediscovery**. Агенту дают только высокоуровневый исследовательский вопрос, ресурсы и ограничения. Дизайн эксперимента, реализация и вывод оригинала скрыты. Это не репликация в духе PaperBench, где агент видит всю статью (§2, Table 1).

Оценивается только **итоговый текстовый вывод**, сравнением с выводом авторов статьи. Численная точность, качество дизайна и обоснованность вывода собственными данными напрямую не оцениваются. Процесс разбирается только постфактум, в анализе ошибок (§5.2).

## Устройство задач

- **Research-problem tree** (§3.1). Статья P раскладывается в дерево T(P): корень — общий вопрос, промежуточные узлы — подвопросы, листья — конкретные эксперименты (датасет D, модель M, критерий C), привязанные к рисунку или таблице. Дерево извлекает gpt-5 Pro при temperature 0 по фиксированному промпту (App. L.1). Качество проверено людьми **только на 5 статьях**: оценки 4.8–5.0 из 5 по пяти критериям (App. I, Table 16).
- **Выбор задачи.** Берётся целевой лист l* (главный рисунок или таблица). Вопрос задачи — его **родитель v***, менее предписывающий. Датасеты и метрика берутся из l*. Эталоном служит результат l*.
- **Отбор статей** (§3.2). Поиск по ICLR/ICML/NeurIPS 2024–2025, затем классификатор на gpt-4o-mini (≈50 кандидатов), затем ручной отбор двумя авторами. Критерии: открытые данные и модели, ≤24 ч на одной A100 80GB, проверяемый вывод с рисунком или таблицей. Итог — **30 статей, одна задача на статью** (Table 7). Фактически в список попали и не только эти три площадки: Nature Comm. Med., TACL, препринты arXiv (Awareness Detection, CoT Faithfulness Gaps от Anthropic).
- **Расширения.** 10 кросс-доменных задач: 5 CV/VLM (VLMs Are Blind, POPE, HallusionBench, MathVista, CharXiv) и 5 по анализу нейросетей (Grokking, Neural Collapse, MaxSup и др.) (App. D, Table 10). Ещё 60 статей разобраны в деревья, но не прогонялись (App. C). Итого «100 статей», реально исполнено 40.
- **Формат задачи** (App. L.2, репозиторий). Файл `instruction.txt`: вопрос, модели с API-обёрткой `utils.llm_inference`, **бюджет API-вызовов** (например 300 или 5000 на модель), пути к данным, метрика, иногда число сэмплов. Эталон `conclusion.txt` — одна-две фразы, **13–49 слов** во всех 35 задачах (подсчитано по репозиторию). Пример (Table 2): вопрос «как точность зависит от позиции релевантной информации в контексте?», эталон «U-образная кривая».
- **Сложность** (App. H). Рубрика из трёх осей по 1–3 баллу: декомпозиция, контроль конфаундеров, сложность анализа. Сумма 3–4 даёт Easy, 5–6 Medium, 7–9 Hard. По Table 6 получается 7 Easy, 13 Medium, 10 Hard.

## Защита от запоминания / контаминации

Это главная слабость работы при выбранном дизайне. Задачи — переоткрытие **опубликованных и широко цитируемых** результатов (Lost in the Middle, «LLMs cannot self-correct yet», CoT without prompting), и модели почти наверняка знают эти выводы.

Что сделано:
1. **Анализ по датам** (§5.4, Table 6; App. E, Table 12). F1 сравнивается на задачах до и после knowledge cutoff (o4-mini 2024-06-01, gpt-5 2024-09-30) внутри каждой категории сложности. Систематического преимущества «до cutoff» нет. Пример для Hard: o4-mini 15.4 → 24.8, gpt-5 22.6 → 31.0, то есть после cutoff даже выше. Но в Medium у gpt-5 падение 44.5 → 23.1, в Easy у o4-mini 58.9 → 42.1. Ячейки маленькие (n=1…8; у gpt-5 в Easy после cutoff n=1). Анализ сделан **только для OpenHands**: для Claude Code и Codex его нет. Авторы сами пишут, что это «absence of a strong signal», а не доказательство отсутствия.
2. **«Структурная» защита** (§5.4). Даже если статья запомнена, вывод якобы требует написать код, запустить и сделать вывод из реальных результатов. **В оценщике этого нет**: проверяется только текст вывода, связь с выполненными экспериментами не проверяется (см. «Метрики»).
3. **Веб-поиск** (§4, сноска 3). Запрет только инструкцией. По словам авторов, ручной просмотр траекторий показал, что агенты не искали статью. Блэклисты сайтов не вводились: для проприетарных агентов это «technically infeasible». По репозиторию фраза «You should NOT use any web search tool or try to answer the question based on your prior knowledge» есть **лишь в 10 из 35** `instruction.txt`. Claude Code запускается с `--dangerously-skip-permissions` без отключения WebSearch/WebFetch (`agents/claude/run.py`).

Чего нет: **пробы без данных** (ответ модели на вопрос без экспериментов), обфускации, контрфактических вариантов, проверки, совпадает ли вывод агента с его собственными числами. При этом формулировки задач **сами указывают на источник**. Например, в Lost in the Middle перечислены ровно модели оригинала (claude-1.3, claude-1.3-100k, mpt-30b-instruct, longchat-13b-16k) и формат его датасета. В Racial Bias вопрос сформулирован как готовая гипотеза («Does GPT-3.5 predict higher medical costs … disproportionately for certain racial groups?»).

## Метрики и оценка

- **Claim-level P/R/F1 по схеме RAGChecker** (§3.3). Вывод агента и эталонный текст (подпись рисунка и проза вокруг) раскладываются на атомарные утверждения. Утверждение агента считается TP, если оно следует хотя бы из одного эталонного утверждения. Precision — доля верных утверждений агента, Recall — доля покрытых эталонных, F1 — их гармоническое среднее. В статье судья gpt-5.2 для всех агентов.
- **По коду** (`eval/RAGChecker/eval.py`, `utils.py`) есть два важных шага. Сначала gpt-5.2 сжимает вывод агента до «core insight», **«omitting all concrete values, specific numbers… methods»**. Затем RAGChecker с extractor/checker **openai/gpt-4.1** (а не gpt-5.2, как написано в статье) сравнивает утверждения. Значит, числа агента не оцениваются вообще, сравниваются только качественные направления трендов. Вспомогательные промпты судьи мягкие: «If it overlaps with part of the ground truth, return True».
- **Валидация судьи** (§3.3, App. J). На 33% эталонных случаев P 0.95, R 0.86, F1 0.89. По App. J это проверка **только разбиения на утверждения** (RAGChecker против человека), а не проверка решения «следует / не следует». κ и согласие между людьми не приводятся.
- **Классификация ложных срабатываний** (§5.1, Table 5): Contradictory / Unrelated / Overgeneralized / Alternative. «Alternative» означает правдоподобный, но иной вывод. Таких 4.5–10.9%, отсюда авторы заключают, что штраф за валидные альтернативные открытия редок.
- **Таксономия ошибок процесса** (§5.2, App. M, Table 17). Четыре стадии: Planning (Method/Goal Deviation), Implementation, Execution (Laziness, Endless loop, Premature termination), Conclusion (Analysis Failure), плюс System errors. В тексте «16 категорий», в Table 17 перечислено 12 для FN. Разметку делает LLM, которой дают траекторию, оригинальную статью и эталон, затем её проверяют авторы. Распределение ошибок — только диагностика, в балл не входит.

## Режим взаимодействия

Агент на основе CLI-coding-агента (OpenHands, Codex, Claude Code) работает в песочнице на узле с 8×A100 80GB. Окружение он ставит сам, доступны shell и файлы. В рабочей директории лежат файл инструкции и данные (§4). «Эксперимент» здесь — реальные вызовы LLM API или локальных HF-моделей; бюджет задаётся числом API-вызовов в тексте инструкции, принудительно не проверяется (не проверено по коду обёртки `LLMInference`). Жёсткого лимита времени нет, большинство прогонов укладывается в час. На кросс-доменных задачах используется бюджет 60 минут. Каждая пара агент–задача прогоняется 3 раза. Обратной связи о правильности до сдачи ответа нет. Ответ — свободный текст в конце лога (JSON `{"result": ...}` или формат конкретного агента).

## Базовые методы и результаты

- **Основные 30 задач** (Table 3). F1: Claude Code (Sonnet-4) **46.7±23.4** (P 52.1, R 48.3), Codex (gpt-5-medium) 41.9±25.4, OpenHands (gpt-5) 37.9±23.0, OpenHands (o4-mini) 31.9±17.6. Прогоны сделаны в основном в августе 2025.
- **Разброс.** Медианный коэффициент вариации 0.37 у Claude Code и >0.6 у OpenHands (§5.1). Lost in the Middle у OH(o4-mini) 57.0±40.5, Awareness Detection у CC 66.7±47.1.
- **По задачам** (Table 14). Лучшее — Lost in the Middle 91.7 (Codex), Persona with Catch 88.6, CoT Without Prompting 82.6 (CC), Hallucination Snowballing 80.9. Худшее — LLM Racial Bias in Medicine: 0.0±0.0 у CC и OH(gpt-5), максимум 34.2. Все агенты пропустили контрольный шаг «убрать расовые маркеры, затем вставить одну метку» (Table 4). Лучший агент по задачам: CC в 13, Codex в 9, OH(gpt-5) в 6.
- **Сложность** (Fig. 3). F1 монотонно падает от Easy к Hard. Авторы считают это валидацией рубрики сложности.
- **Ошибки** (Fig. 2). Доминируют Planning (Method/Goal Deviation) и Conclusion (Analysis Failure), а не реализация.

## Ограничения и критика

- **Запоминание фактически не контролируется** (см. выше). Задачи построены на знаменитых выводах. Оценщик сравнивает только качественный вывод без чисел. Пробы без данных нет. Значит, агент, который пересказал запомненный вывод поверх формально выполненного эксперимента, получит полный балл. Отсутствие эффекта cutoff на n=1…8 и только для OpenHands мало что доказывает. Высокий F1 на самых известных задачах (Lost in the Middle 91.7) согласуется и с гипотезой запоминания.
- **Эталон — вывод одной статьи, а не истина.** В примере App. J агент провёл корректный по виду контрфактический эксперимент на gpt-3.5-turbo и не нашёл расового сдвига. Это получило 0, потому что эталон говорит обратное. Поведение моделей за API со временем меняется, так что «переоткрыть» результат 2023 года на текущем gpt-3.5-turbo может быть невозможно в принципе. Авторы это не обсуждают.
- **Эталоны короткие** (13–49 слов): часто это 1–3 атомарных утверждения. Отсюда F1 сильно квантован (0, 33, 50, 67…), и огромный разброс отчасти является артефактом квантования.
- **Валидация судьи неполная.** Проверено разбиение на утверждения, но не проверено решение об entailment. Модель судьи в коде (gpt-4.1) не совпадает с заявленной в статье (gpt-5.2).
- **Method Deviation считается ошибкой по определению.** Отклонение от метода авторов квалифицируется как провал планирования, даже если альтернативный дизайн валиден. Дерево по замыслу отражает «траекторию авторов», а не все корректные пути (§3.1).
- **Утечки в формулировках.** Списки моделей оригинала, вопрос-гипотеза да/нет, в части задач число сэмплов и метрика. Всё это заметно сужает пространство дизайна.
- **Нет отрицательных случаев.** Нет задач, где «эффекта нет», и вариантов с инвертированным эффектом.
- **Узкий домен.** Только поведение LLM и немного CV/NN. Масштаб «100 статей» в основном нереализованный: исполнено 40, а 153 задачи unverified собраны без людей.

## Практика запуска

`pip install -r requirements.txt` (torch, transformers, openai, anthropic, google-genai, litellm, ragchecker, refchecker). Нужны ключи OpenAI (оценщик, большинство экспериментов), Anthropic, Google, HF. Запуск: `bash run_experiment.sh` → `run_agent.py` с параметрами `--AGENT_ID/--TASK_ID/--LLM_MODEL/--RUN_TIMES`, оценка через `bash run_eval.sh`. Для своего агента можно взять задачи с HF и писать лог в формате `log/<agent>/<model>/<task>/<ts>/log.log` (README). Песочницы в строгом смысле нет. Claude Code запускается на хосте с `--dangerously-skip-permissions`, а в рабочую директорию агента пишется `.env` со всеми ключами. OpenHands работает в Docker. Часть задач требует GPU (локальные HF-модели). Стоимость агентного прогона $0.15–0.84 за задачу (Table 13), плюс API-вызовы экспериментов и оценщика.

## Релевантность для нашего проекта

**Пересечение с нашими заявками о новизне — слабое.** FIRE-Bench — бенчмарк *переоткрытия*, но не абдукции. Нет T0, которая даёт сбой. Нет выбора «новая сущность против изменённого закона». Нет отрицательных и парных случаев. Нет границ применимости. Нет ступеней a→b→c→d. Нет числового закона. Домен — эмпирика поведения LLM, а не физика. Ни один из четырёх пунктов §5 `benchmark_comparison.md` не затронут. Общее у нас только одно: эталон — известный опубликованный результат, ответ — вывод словами, оценка — LLM-судья по атомарным утверждениям.

**Главная ценность для нас — как отрицательный пример защиты от запоминания.** Статья ICML 2026 прямо ставит вопрос «не запомнены ли статьи?» и отвечает на него только сравнением по cutoff. Это хороший аргумент в related work, почему нужны наши ступени (b)–(d) и проба без данных на каждой ступени. Можно сформулировать так: «FIRE-Bench контролирует контаминацию только по датам публикации (n≤8 на ячейку, один агент), без пробы без данных и без контрфактических вариантов; оценщик игнорирует числа».

Что заимствовать:
- **Claim-level P/R/F1** для части III (объяснение словами). Разложить эталонное объяснение варианта на атомарные утверждения и считать recall/precision отдельно. Это лучше одного балла рубрики и даёт интерпретируемую precision («сколько лишнего наговорил»).
- **Классификация ложных утверждений** Contradictory / Unrelated / Overgeneralized / Alternative. Особенно полезен класс «Overgeneralized» для наших границ применимости: утверждение шире, чем поддерживают данные.
- **Таксономию ошибок по стадиям** (Planning / Implementation / Execution / Conclusion, с Laziness, Premature termination, Analysis Failure) можно взять как основу разметки логов режима 2.
- **Рубрику сложности** по трём осям (декомпозиция, конфаундеры, анализ) можно взять для паспорта каждой нашей задачи.

Подводные камни, которых избегать:
- Не сжимать ответ агента до «core idea» без чисел перед судейством. У нас закон оценивается числом, но в объяснении тоже нужны количественные утверждения: масса возмущающего тела, энергия, уносимая нейтрино.
- Валидировать **решение судьи** (entailment), а не только разбиение на утверждения. Заявленная и фактическая модели судьи должны совпадать.
- Не полагаться на запрет веба в инструкции. Нужна реальная изоляция (у нас уже есть venv и раннер, сетевую изоляцию стоит проверить). Ключи в рабочей директории агента недопустимы.
- Не вставлять в промпт отпечатки источника: исторические имена, характерные модели, формулировку вопроса как готовой гипотезы. Для нас это прямо относится к ступени (a) и к утечкам в (b).
- Эталон должен быть **истиной генератора**, а не мнением одной статьи. У нас данные симулируются, так что это уже решено. Аргумент стоит явно привести против дизайна «переоткрытия публикаций».
