# Бенчмарк абдукции знания: бета-распад и Нептун/Вулкан

Дата: 2026-11-12. Статус: черновик на согласование. Основа: `literature/physics_new_knowledge.pdf`, переход №11 «бета-спектр → нейтрино». Пара «Нептун/Вулкан» в обзоре отсутствует и добавлена как парный отрицательный случай абдукции.

## 1. Зачем это

Проверить, может ли агент (LLM в песочнице) совершить абдукцию: по данным и известной, но дающей сбой теории T0 восстановить закон, определить границы его применимости и объяснить механизм человеческим языком. Не «подогнать кривую», а выбрать объясняющую гипотезу, в частности решить, нужна ли новая сущность.

Вторая цель: отделить открытие от запоминания. Для этого каждая задача существует на четырёх ступенях, от узнаваемой исторической до полностью синтетической. Разность результатов между ступенями оценивает вклад запоминания.

## 2. Цели, не-цели, анти-цели

**Цели**
- Два режима одной задачи: (1) готовая таблица + Python-песочница; (2) интерактивный симулятор с бюджетом измерений.
- Результат агента из трёх частей: I) закон в `law.py`, II) границы применимости, III) объяснение словами (оба последних в `answer.md`).
- Автоматическая числовая оценка закона; рубрика + LLM-судья для границ и объяснения; человек может перечитать тот же `answer.md`.
- Четыре ступени: (a) исторический, (b) обфусцированный, (c) контрфактический, (d) синтетический.
- Отрицательные случаи: задачи, где правильный ответ «новой сущности нет».
- Запуск через Claude Code с песочницей; прогон отделён от оценки.

**Не-цели**
- Остальные 28 переходов из обзора. Это первая пробная пара, дизайн должен позволять добавлять задачи.
- Реальные исторические данные (в этой версии всё симулируется; реальные эфемериды можно добавить позже).
- Лидерборд, UI и веб-интерфейс любого рода, в том числе для ручной разметки (отчёт только через Quarto, постфактум, см. 6а).
- Задачи класса «теория против теории» (СТО/ОТО/QFT), не про данные.

**Анти-цели (провал, даже если всё запускается)**
- Бенчмарк превращается в символьную регрессию: высокий балл за fit без объяснения.
- Утечки ответа через имена переменных, названия файлов, комментарии, порядок столбцов, историю git, сообщения об ошибках.
- Агент получает хорошую оценку, постулируя новую сущность всегда (или никогда). Парные задачи должны это наказывать.
- Эталон (истинный закон, рубрики) доступен из песочницы агента.

## 3. Задачи

Каждая задача задаётся конфигурацией генератора (seed, ступень, уровень шума, число точек, систематика). Несколько seed на вариант для оценки разброса.

### 3.1 Бета-распад (абдукция скрытой сущности)

**T0, которую видит агент:** двухчастичный распад «родитель → дочернее ядро + электрон» с сохранением энергии и импульса. Предсказание T0: электрон моноэнергетичен (линия при энергии, заданной разностью масс Q).

**Данные:** события распада: кинетическая энергия электрона, энергия и направление отдачи ядра (если измерены), разность масс Q (из отдельной «таблицы масс»), метаданные детектора (разрешение, пороги).

**Аномалия:** спектр электрона непрерывный от 0 до Q; сумма импульсов электрона и ядра не уравновешивается.

**Варианты на каждой ступени:**
- *Положительный:* истина — трёхчастичный распад с нейтральной лёгкой частицей. Закон: форма спектра ∝ p·E·(Q−T)² для безмассовой частицы (форма в других ступенях меняется, см. ниже); дополнительно корреляция электрон-отдача.
- *Отрицательный:* истина — артефакт детектора (отклик с хвостом энергетических потерь и обратным рассеянием вокруг линии при T0-энергии). Новой частицы нет. Отличие от положительного: наличие линии при полной энергии, форма хвоста, зависимость от толщины мишени/углов; при импульсах отдачи баланс сохраняется.

**Альтернативные гипотезы, которые агент должен рассматривать:** нарушение сохранения энергии (статистически), артефакт детектора, скрытая частица (одна или несколько).

**Границы (эталон):** конечная точка Q (чувствительность к массе скрытой частицы), низкоэнергетический режим (кулоновская поправка, зависящая от Z), диапазон применимости формы спектра (разрешённый переход).

**Ступени:**
- (a) реальные названия (нейтрино, тритий/RaE-подобные значения), реалистичные константы;
- (b) та же структура, переименованные частицы и единицы, перемасштабированные величины;
- (c) контрфактический закон: скрытая частица с массой, составляющей заметную долю Q, или иная степень в форме спектра; запомненный ответ «(Q−T)²» неверен;
- (d) синтетический мир: вымышленные частицы, свой закон сохранения, число скрытых частиц и спектральная форма задаются генератором (например, две скрытые частицы → степень 5).

### 3.2 Нептун против Вулкана (абдукция сущности против изменения закона)

**T0:** ньютоновская гравитация + известные тела (Солнце и известные планеты).

**Данные:** временной ряд астрометрических положений целевой планеты и её невязки относительно предсказаний T0; для режима 2 доступны дополнительные «наблюдательные» запросы (положения других тел, поиск «транзитов»/слежение в заданной области неба).

**Варианты на каждой ступени:**
- *Нептун-подобный (положительный):* невязки орбиты внешней планеты создаёт невидимый внешний возмущающий объект. Закон: орбита и масса возмущателя, предсказание невязок и положения на небе. Согласуется с независимыми проверками (поиск в предсказанной точке находит объект).
- *Вулкан-подобный (отрицательный):* вековая прецессия перигелия внутренней планеты. Гипотеза «внутренний возмущатель» подгоняется для одной планеты, но не согласуется с независимыми данными (невязки других внутренних планет несовместимы с единым возмущателем, поиск в предсказанной области пуст). Истина: поправка к закону притяжения (например, добавка ∝ 1/r³ в силе).

**Границы (эталон):** временное окно и область, где работает найденный закон; вырождения (например, масса/расстояние возмущателя); область, где поправка к закону незаметна.

**Ступени:**
- (a) реальные названия (Уран, Меркурий, Солнце, Нептун, Вулкан), реалистичные параметры;
- (b) переименованные тела, единицы и шкалы;
- (c) контрфактический закон: сила ∝ 1/r^{2+δ} при заметном δ, либо иная форма поправки; запомненный ответ «1/r², GR-прецессия» неверен;
- (d) синтетическая система: вымышленные тела и законы из генератора.

### 3.3 Состав набора

4 варианта на ступень: бета положительный, бета отрицательный (артефакт), Нептун-подобный, Вулкан-подобный. Итого 4 × 4 ступени = 16 вариантов, каждый в нескольких seed и в 2 режимах. Порядок реализации: сначала ступени (a) и (c) для бета положительный и Нептун/Вулкан в режиме 1, затем (b), (d), затем режим 2, затем отрицательный бета.

## 4. Формат ответа агента

Агент пишет в рабочую папку:
1. `law.py` с функцией `law(...)` фиксированной сигнатуры (задаётся в описании задачи) и словарём `DOMAIN` с числовыми границами применимости, где это осмысленно. Должен быть чисто детерминированным, без чтения файлов и сети, укладываться в ограничение по времени.
2. `answer.md` с разделами: **Закон** (формула словами и ссылка на `law.py`), **Границы применимости**, **Объяснение** (механизм, почему он, а не альтернативы; что бы опровергло гипотезу; какие альтернативы рассмотрены и отвергнуты).

## 5. Оценка

**I. Закон (автоматически, `law.py`).**
- Ошибка предсказания на скрытых точках внутри диапазона и вне его (экстраполяция, новый режим).
- Структурное совпадение с истинным законом там, где это определено (параметры, степени, форма). Сложность найденной формулы (число параметров/узлов AST) сообщается отдельно, как мера сжатия.
- Для положительных/отрицательных пар: верное решение «нужна ли новая сущность» (флаг, который агент выставляет в `answer.md` в машинно читаемом поле, например `ENTITY: yes|no`).

**II. Границы.**
- Числовая часть: `DOMAIN` против истинных границ (например, положение конечной точки спектра, временное окно).
- Рубрика для прозы.

**III. Объяснение (рубрика + LLM-судья).**
Для каждого варианта заранее пишется список бинарных пунктов с критерием и ссылкой на фрагмент текста. Примеры: назван скрытый объект; указано, какой закон сохранения спасается; перечислены альтернативы и объяснено, почему они отвергнуты; предложен эксперимент, различающий альтернативы; не объявлена новая сущность там, где её нет (для отрицательных случаев); объяснение понятно без формул. Судья видит `answer.md`, рубрику и описание истины, но не `law.py`. Часть ответов проверяется вручную для калибровки судьи; судья должен быть другой моделью или хотя бы другим промптом, чем тестируемая.

**Итог и контаминация.** Метрики сообщаются по ступеням (a)–(d). Главный показатель запоминания — падение качества между (a) и (d) и между (a) и (c). Отдельная необязательная проба: тот же вопрос без данных, чтобы проверить, знает ли модель ответ заранее.

**Режим 2 (интерактив).** Дополнительно: результат при заданном бюджете, доля бюджета, потраченная на измерения, различающие альтернативы, и общая информационная эффективность. Журнал запросов сохраняется.

## 6. Среда запуска

- Каждая задача: отдельная чистая папка с описанием, таблицей данных (режим 1) или командой-симулятором с бюджетом (режим 2) и ничем лишним. Эталоны и рубрики лежат вне доступной агенту области.
- Запуск через Claude Code в песочнице: доступны чтение/запись в папке задачи, запуск Python; сеть и веб-поиск отключены; ограничения по времени и токенам; история диалога сохраняется для разбора.
- Прогон и оценка отделены: раннер только создаёт папку, запускает агента и забирает `law.py` и `answer.md`; оценщик работает отдельно над сохранёнными ответами.

## 6а. Отчёт

Никакого UI и веб-интерфейса не нужно. Результаты оформляются отчётом на Quarto. Отчёт строится постфактум отдельным шагом поверх сохранённых результатов оценки (таблицы по ступеням, оценки рубрик, журналы запросов в режиме 2). Агент отчётом не занимается: его задача только закон, границы и объяснение, то есть абдукция.

## 7. Ограничения

- Python, numpy/scipy, без тяжёлых расчётов (симуляции быстрые, воспроизводимые по seed).
- Все симуляторы детерминированы по seed; шум, число точек, систематика конфигурируются.
- Реалистичность не цель: цель в сохранении эпистемической структуры (аномалия, альтернативы, различающие эксперименты).

## 8. Оставлено строителю

Точные формулы и параметры симуляторов (в рамках описанных структур); сигнатуры `law(...)`; формат конфигов; реализация песочницы и раннера; конкретные тексты рубрик; пороги для числовых метрик; структура репозитория; выбор судьи.

## 9. Решения, принятые мной (не обсуждались, можно оспорить)

- Язык Python.
- **Описания задач для агентов на английском** (документ дизайна на русском). Причина: меньше артефактов языка в результатах и профиле утечек. Если цель включает оценку на русском, поменять.
- Поле `ENTITY: yes|no` в `answer.md` для машинной проверки решения о новой сущности.
- Словарь `DOMAIN` в `law.py` для числовой проверки границ.
- Отрицательный бета-случай реализуется через артефакт детектора.
- **Общая сигнатура в паре.** Положительный и отрицательный варианты пары имеют одинаковую сигнатуру `law(...)`, одинаковую T0 и один и тот же вид данных; различается только истина в генераторе. Бета: `law(T)` возвращает плотность распределения электронов по кинетической энергии, как её видит детектор (в отрицательном случае это линия плюс хвост отклика, в положительном непрерывный спектр). Нептун/Вулкан: `law(t)` возвращает невязку/положение целевой планеты как функцию времени. Иначе сигнатура выдавала бы ответ.
- **Метрика «всегда да / всегда нет».** `ENTITY` засчитывается на уровне пары: пара считается решённой, только если верны оба члена. Постоянный ответ даёт 0 по парной метрике.
- **Контаминация.** Падение между ступенями (a) и (c)/(d) считается грубым индикатором. Чтобы отделить его от роста сложности, на каждую ступень добавляется эталонный решатель (oracle): он знает семейство структуры и подбирает только константы. Результат агента нормируется на результат oracle.
- **Агрегация.** Единого итогового числа нет; основной выход — таблица по ступеням и вариантам. По умолчанию 5 seed на вариант, один прогон агента на seed. Число seed можно менять.
- **Утечки в ступени (b).** В план входит аудит узнаваемости: независимой модели дают описание и данные (b) без подсказок и спрашивают, какое известное открытие это. Если узнаёт, переименование усиливается.
- **Режим 2.** Интерфейс: CLI-команды симулятора (`measure ...`), бюджет в единицах стоимости запросов (у разных типов запросов разная цена, например «поиск в области неба» дороже). «Различающие» запросы определяются заранее, по списку типов запросов, заданному для каждого варианта в генераторе, без ручной разметки.
- **Модели и затраты.** Тестируются модели Claude через Claude Code. Лимиты времени и токенов на прогон задаются в конфиге; конкретные значения выбираются при реализации. Судья — отдельная модель или отдельный промпт.
- Документ лежит в `docs/design.md`, репозиторий пока не под git.
