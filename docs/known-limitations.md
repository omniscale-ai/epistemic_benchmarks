# Известные ограничения и решения до первого реального прогона

Статус на 2026-11-12: реализованы все 13 задач плана, тесты проходят (312 passed, 1 skipped — рендер Quarto, так как quarto не установлен). Ниже то, что НЕ исправлено и требует решения или проверки человеком.

## Нужно решить / сделать перед реальными прогонами
1. **Изоляция агента (I1).** Агент запускается как тот же пользователь ОС, Bash разрешён. Через Bash можно прочитать `rubrics/`, исходники генераторов, каталог состояния (бюджет в режиме 2). Для честных прогонов нужен контейнер/bwrap или отдельный пользователь ОС; в режиме 2 симулятор лучше отдавать через прокси вне репозитория. Остаток C1: каталог результатов `runs_root/<variant_id>/` создаётся до запуска агента и виден через `ls ../../..` (cwd агента теперь нейтральный, но выше по дереву имя варианта достижимо). Простой фикс: создавать каталог результатов после завершения агента или держать его вне `runs_root`.
2. **Асимметрия цели в орбитальной паре (I4).** Для entity целевая планета внешняя, для no_entity внутренняя (как Уран/Меркурий). Агент может отвечать «внешняя → скрытая планета, внутренняя → изменённый закон» без анализа данных. Варианты: одна и та же цель в обоих случаях (нужна перенастройка силы сигнала), либо считать и публиковать базовый «безэвиденсный» ответ в таблицах.
3. **Бета: окно экстраполяции** — исправлено дополнением (docs/design-addendum-mechanism.md): публичное окно `(0.25 Q, 1.2 Q)`, экстраполяция отложена ниже 0.25 Q и выше 1.2 Q.
4. **Орбита entity** больше не решается подгонкой кривой: закон оценивается на 10–40 лет вне окна данных (`EXT_YR = 40`), плюс явная проверка `MECHANISM`.
5. **Beta no_entity, стадии a/c/d** физически одинаковы (m_X влияет только на entity), поэтому разрыв a→c, a→d там ≈ 0 по построению.
6. **Живой прогон CLI не выполнялся.** Флаги `claude -p` (агент: `--restricted --tools ... --permission-prompts none ...`; судья/аудит: `--tools "" --setting-sources ""`) проверены только по `claude --help`. Перед массовым запуском один пробный прогон с маленьким `max_budget_usd` (по умолчанию долларовый лимит выключен; прогон ограничен таймаутом и бюджетом симуляций).
7. **Quarto** не установлен: `report/report.qmd` проверен только исполнением его python-ячеек на фикстуре.
8. **Судья** и **аудит** используют ту же модель (`sonnet`), что и агент по умолчанию; отличается только промпт. Можно задать другую модель константами `JUDGE_MODEL`/`AUDIT_MODEL`.

## Состояние оценки механизма (после дополнения)
- Ошибки предсказания нормируются по областям (внутри окна / вне окна) отдельно.
- `MECHANISM` оценивается автоматически (`evaluate/mechanism.py`); допуски лежат в `true_mechanism["tolerance"]` (агент их не видит, смоук подаёт оракулу копию без допусков).
- Вид `"other"` никогда не даёт баллов (ни `kind_ok`, ни параметры): он нужен только как выход для нераспознанной гипотезы; такие ответы оценивает судья по рубрикам.
- Принятый компромисс: перечисление допустимых `kind` в task.md раскрывает классы гипотез (скрытое тело / поправка к силе; скрытые носители / отклик детектора); оно симметрично для entity и no_entity и включает `"other"`.
- Орбита, entity: параметры скрытого тела плохо идентифицируемы по 10 годам, поэтому оценивается только большая полуось `a` с множительным допуском ×/÷ 1.3; масса не оценивается.
- Оракл в бете, стадия d: подгонка `k` отличается от истины примерно на 0.15.
- Смоук проверяет, что кривая без `MECHANISM` получает хорошие метрики предсказания, но `mech_status == "missing"`, а ответ с чужим видом механизма даёт `kind_ok = False`.
