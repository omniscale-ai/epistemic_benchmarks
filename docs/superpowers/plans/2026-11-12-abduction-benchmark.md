# Abduction Benchmark Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a benchmark that gives an agent (Claude Code in a sandbox) data from a simulated physics world and scores the law, validity limits and explanation it returns, on beta decay and Neptune/Vulcan tasks across four contamination stages.

**Architecture:** Deterministic, seed-driven generators (`build_task(cfg) -> TaskBundle`) produce a public workspace folder (what the agent sees) and hidden truth (regenerated by the evaluator from the same cfg, never stored in the workspace). A runner launches the agent; a separate evaluator scores `law.py` numerically, parses `answer.md`, applies a rubric through an LLM judge, and aggregates by pair and stage; a Quarto report is rendered afterwards from saved results.

**Tech Stack:** Python 3.11+, numpy, scipy, pandas, pytest, PyYAML, Quarto (post-hoc report only), Claude Code CLI (`claude -p`) for both agent and judge.

**Spec:** `docs/design.md`

## Global Constraints

- Python; numpy/scipy only, no heavy compute; all simulators deterministic by seed.
- No UI or web interface of any kind; report only via Quarto, built post-hoc, never by the agent.
- Agent-facing task text in English; design doc stays Russian.
- 4 variants per stage (beta entity, beta no_entity, orbit entity, orbit no_entity) × 4 stages (a,b,c,d) = 16 variants; default 5 seeds per variant, 1 agent run per seed; two modes (1 = table + Python sandbox, 2 = interactive simulator with budget).
- Agent output: `law.py` (fixed-signature `law(...)` plus `DOMAIN` dict) and `answer.md` (sections Law / Limits / Explanation, plus machine-readable line `ENTITY: yes|no`).
- Truth, rubrics and oracle live outside the agent-accessible directory; agent has no network and no web search; judge never sees `law.py` and is a different model or different prompt from the tested one.
- Shared signature within a pair: beta `law(T: np.ndarray) -> np.ndarray` (detector-seen energy density); orbit `law(t: np.ndarray) -> np.ndarray` (longitude residual of target planet, arcsec).
- `ENTITY` is scored per pair (both members correct), so constant answers score 0.
- No single headline number; output is per-stage/per-variant tables, normalized by the oracle solver.
- Implementation order of value: stages (a),(c) for beta-entity and Neptune/Vulcan in mode 1 first, then (b),(d), then mode 2, then beta no_entity.

## Review Focus

1. `law.py` that crashes, hangs, returns wrong shape or NaN/inf → scored as failure with a recorded reason, never crashes the evaluator (Task 5).
2. `answer.md` with missing, duplicated or malformed `ENTITY` line or missing sections → explicit parse error status, counted as wrong for the pair (Task 6).
3. Agent tampers with the budget ledger or reads outside the workspace in mode 2 → ledger lives outside the workspace; overspend rejected (Tasks 9, 10).
4. Public files leak truth (variant names, `truth`, "neutrino", "Vulcan", true constants) in stages (b)-(d) → leakage test fails the build (Task 4).
5. Judge returns malformed or partial JSON → retried once, then recorded as `judge_error`, never silently scored as pass (Task 8).

### Task 3: Neptune/Vulcan generator

**Files:**
- Create: `src/abductbench/tasks/orbit.py`
- Test: `tests/test_orbit.py`

**Interfaces:**
- Consumes: Task 1 types, `build_task` dispatch.
- Produces: `build_orbit(cfg: VariantConfig) -> TaskBundle`; `law(t) -> longitude residual (arcsec)` of the target planet.

Spec values:
- Planar N-body integrator (leapfrog or `scipy.integrate`), GM_sun = 4π² AU³/yr², T0 = Newtonian gravity with known bodies.
- `entity` (Neptune-like): hidden outer perturber, residuals of an outer target planet; cross-check data (`other_residuals.csv`) small/consistent with the perturber.
- `no_entity` (Vulcan-like): extra radial force ∝ k/r^n (n=3 in stage (a)), producing secular perihelion precession of the target (inner planet); a single-interior-perturber fit to the target alone works but fails on `other_residuals.csv` (other inner planets' residuals scale with 1/r^n, inconsistent with one perturber).
- Stage (c): force exponent 2+δ (δ ≥ 0.3) for the whole system or a different correction form so the memorized GR/Newton answer is wrong; (d): invented system and constants; (b): renamed bodies, units, scales.
- Public: `task.md`, `target_positions.csv`, `other_residuals.csv`, `known_bodies.csv`, `t0_model.py` (T0 predictor the agent can call). `true_domain`: valid time window and orbital radii range. `discriminating_queries`: `{"search_region","other_body_residuals"}`.

- [ ] **Step 1: Write failing tests**: `test_entity_residuals_nonzero_vs_t0` (max |residual| > 5× noise), `test_no_entity_single_perturber_fails_crosscheck` (fit a one-perturber model to the target residuals; its prediction for another inner planet misses by > 3σ while the true correction law matches), `test_pair_shares_signature`, `test_deterministic_by_seed`, `test_stage_c_law_differs`.
- [ ] **Step 2: Run** `pytest tests/test_orbit.py -v`; expect FAIL.
